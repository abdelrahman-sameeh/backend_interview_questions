## 1. What is Singleton?

Singleton is a pattern. It makes sure a class has **only one object**. Every part of
the app uses this same object.

## 2. Why do we use it?

- To share one object for things that cost a lot (like a database connection).
- To keep the same data in one place.
- To not create the same object many times.

## 3. Code example in PHP

```php
class Database
{
    private static ?Database $instance = null;

    private function __construct() {}

    public static function getInstance(): Database
    {
        return self::$instance ??= new self();
    }
}

Database::getInstance() === Database::getInstance(); // true
```

## 4. Why is the constructor private?

We make it private to stop people from using `new Database()`. The only way to get
the object is `getInstance()`.

## 5. Why block clone and __wakeup?

`clone` and `unserialize()` can make a second object. This breaks the rule of "only
one object". So we block them.

```php
private function __clone() {}
public function __wakeup() { throw new \Exception('Cannot unserialize singleton.'); }
```

## 6. Singleton vs Static Class

| Singleton | Static Class |
|---|---|
| It is a real object | It is not an object |
| It is made only when needed | It is ready right away |
| It can save data inside it | Its data is always global |

## 7. Problems with Singleton

- It uses global data. This makes testing harder.
- It hides what a class needs (a hidden dependency).
- It can cause bugs in apps that run for a long time (like Swoole).

## 8. How Laravel uses it

Laravel can make a singleton with the container. We don't need `getInstance()`:

```php
$this->app->singleton(PaymentGateway::class, fn () => new StripeGateway(config('services.stripe.key')));
```

## 9. Singleton vs Dependency Injection

A classic Singleton puts the "only one object" rule inside the class. A Dependency
Injection container can also give "only one object", but the class stays simple and
easy to test. It is better to use this way.

## 🎯 Main Idea

Singleton = one object, used everywhere. It is better to let a container manage this,
instead of writing `getInstance()` by hand.

## الترجمة بالعربي

### 1. ايه هو الـ Singleton؟
Singleton باترن بيضمن ان الكلاس يبقاله **object واحد بس**. كل حاجة في التطبيق بتستخدم نفس الـ object ده.

### 2. ليه بنستخدمه؟
- نشارك object واحد لحاجة مكلفة (زي اتصال بقاعدة بيانات).
- نحافظ على نفس البيانات في مكان واحد.
- منعملش نفس الـ object أكتر من مرة.

### 3. الكود في PHP
زي ما هو فوق: كلاس `Database` بيه `getInstance()` تعمل return لنفس الـ instance كل مرة.

### 4. ليه الـ constructor خاص (private)؟
عشان نمنع حد يعمل `new Database()`. الطريقة الوحيدة نجيب بيها الـ object هي `getInstance()`.

### 5. ليه بنمنع clone و __wakeup؟
`clone` و `unserialize()` ممكن يعملوا object تاني، وده بيكسر قاعدة "object واحد بس"، فبنمنعهم.

### 6. Singleton vs Static Class
| Singleton | Static Class |
|---|---|
| object حقيقي | مش object |
| بيتعمل لما نحتاجه بس | جاهز على طول |
| ممكن يحمل بيانات جواه | بياناته دايمًا عامة |

### 7. مشاكل الـ Singleton
- بيستخدم بيانات عامة (global) وده بيصعّب الاختبار.
- بيخفي احتياج الكلاس (dependency مخفية).
- ممكن يسبب مشاكل في تطبيقات شغالة لفترة طويلة (زي Swoole).

### 8. لارافيل بتستخدمه ازاي؟
لارافيل بتعمل singleton عن طريق الـ container من غير ما نحتاج `getInstance()`.

### 9. Singleton vs Dependency Injection
الـ Singleton التقليدي بيحط قاعدة "object واحد" جوه الكلاس نفسه. أما الـ DI container
بيدّي نفس النتيجة بس الكلاس بيفضل بسيط وسهل الاختبار. الأفضل نستخدم الطريقة دي.

### 🎯 الفكرة الأساسية
Singleton = object واحد يتستخدم في كل مكان. الأفضل نسيب الـ container يدير الموضوع ده،
بدل ما نكتب `getInstance()` بإيدينا.
