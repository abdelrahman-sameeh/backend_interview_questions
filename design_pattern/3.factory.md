## 1. What is Factory?

Factory is a pattern. It puts the code for making new objects in one place. We do not
write `new SomeClass()` in many places. We ask the Factory for an object, and we don't
need to know its exact class.

## 2. Why do we use it?

- It hides the details of how an object is made (which class, which arguments).
- It is easy to add a new type without changing the other code.
- It is good when the object type depends on a condition (like a payment name).

## 3. Code example in PHP

```php
interface PaymentGateway { public function charge(int $amount): void; }

class StripeGateway implements PaymentGateway {
    public function charge(int $amount): void { /* ... */ }
}

class PaypalGateway implements PaymentGateway {
    public function charge(int $amount): void { /* ... */ }
}

class PaymentGatewayFactory
{
    public static function make(string $type): PaymentGateway
    {
        return match ($type) {
            'stripe' => new StripeGateway(),
            'paypal' => new PaypalGateway(),
            default  => throw new \InvalidArgumentException("Unknown gateway: $type"),
        };
    }
}

$gateway = PaymentGatewayFactory::make('stripe');
$gateway->charge(1000);
```

## 4. Factory Method vs Simple Factory

- **Simple Factory**: one method (with a switch/match) that returns different classes.
  This is the example above.
- **Factory Method**: a method in a base class. Child classes change this method to
  make their own object. The creation logic is in the child classes, not in one place.

## 5. Factory vs Abstract Factory

- **Factory**: makes one product (like one `PaymentGateway`).
- **Abstract Factory**: makes a **group of related products** (like a `Button`,
  `Checkbox`, and `Input` that match the same theme).

## 6. How Laravel uses it

- `Model::factory()` — makes fake models for testing and seeding.
- The service container also works like a Factory: `app()->make(SomeClass::class)`
  builds the object and gives it what it needs.

## 7. Problems with Factory

- It adds an extra class when we only have one real type. A simple `new` may be enough.
- The Factory can grow into a big `match`/`switch`. We can fix this with a map of
  `type => class`.

## 🎯 Main Idea

Factory puts **how objects are made** in one place. Other code depends on an interface,
not a real class. This is good when the creation logic can change.

## الترجمة بالعربي

### 1. ايه هو الـ Factory؟
Factory باترن بيحط كود عمل الـ objects الجديدة في مكان واحد. منكتبش `new SomeClass()`
في أماكن كتير. بنطلب object من الـ Factory، ومش لازم نعرف الكلاس بالظبط بتاعه.

### 2. ليه بنستخدمه؟
- بيخبّي تفاصيل عمل الـ object (أنهي كلاس، أنهي arguments).
- سهل نضيف نوع جديد من غير ما نغيّر باقي الكود.
- كويس لما نوع الـ object بيعتمد على شرط (زي اسم وسيلة الدفع).

### 3. الكود في PHP
زي المثال فوق: `PaymentGatewayFactory::make('stripe')` بترجع الكلاس المناسب
(`StripeGateway` أو `PaypalGateway`) حسب النوع المطلوب.

### 4. Factory Method vs Simple Factory
- **Simple Factory**: method واحدة (فيها switch/match) بترجع كلاسات مختلفة.
- **Factory Method**: method في كلاس أساسي، والكلاسات الفرعية بتغيّرها عشان تعمل
  الـ object بتاعها. منطق الإنشاء بيبقى في الكلاسات الفرعية مش في مكان واحد.

### 5. Factory vs Abstract Factory
- **Factory**: بيعمل product واحد (زي `PaymentGateway` واحد).
- **Abstract Factory**: بيعمل **مجموعة products مترابطة** (زي `Button` و `Checkbox`
  و `Input` متناسقين مع بعض).

### 6. لارافيل بتستخدمه ازاي؟
- `Model::factory()` — بتعمل موديلات وهمية للاختبار والـ seeding.
- الـ service container نفسه شغال كـ Factory: `app()->make(SomeClass::class)`.

### 7. مشاكل الـ Factory
- بيضيف كلاس زيادة لو فيه نوع حقيقي واحد بس، وممكن `new` عادية تكفي.
- الـ Factory ممكن تكبر لـ `match`/`switch` كبيرة، ونقدر نصلحها بـ map بتربط
  النوع بالكلاس.

### 🎯 الفكرة الأساسية
الـ Factory بيحط **إزاي بيتعمل الـ objects** في مكان واحد. باقي الكود بيعتمد على
interface مش كلاس حقيقي. ده كويس لما منطق الإنشاء ممكن يتغيّر.
