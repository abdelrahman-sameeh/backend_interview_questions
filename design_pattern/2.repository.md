## 1. What is Repository?

Repository is a layer. It sits between your business logic (controllers, services)
and your data (database, API, cache). Your code talks to the Repository, not to the
database directly.

## 2. Why do we use it?

- It separates business logic from the data source.
- It is easy to change the data source later (MySQL → API → cache).
- It is easier to test. We can use a fake Repository instead of a real database.
- It puts all the query code in one place.

## 3. Laravel example

```php
interface UserRepositoryInterface
{
    public function find(int $id): ?User;
    public function create(array $data): User;
}

class EloquentUserRepository implements UserRepositoryInterface
{
    public function find(int $id): ?User { return User::find($id); }
    public function create(array $data): User { return User::create($data); }
}

class UserController extends Controller
{
    public function __construct(private UserRepositoryInterface $users) {}

    public function show(int $id) { return $this->users->find($id); }
}
```

## 4. Repository vs Eloquent Model

| Eloquent Model | Repository |
|---|---|
| It is one table/row in the database | It is a layer over the data source |
| It is tightly connected to the ORM | It can hide the ORM behind an interface |
| Hard to change the data source | Easy to change the data source |

## 5. Why do we use an Interface?

Our code depends on `UserRepositoryInterface`, not on the real class. So we can change
the data source (Eloquent → API), or use a fake Repository in tests. We don't need to
change the other code.

## 6. Binding in the service container

```php
public function register(): void
{
    $this->app->bind(UserRepositoryInterface::class, EloquentUserRepository::class);
}
```

## 7. Repository vs Service Layer

- **Repository**: only gets and saves data.
- **Service**: has the business logic. It can use one or more Repositories.

Normal flow: `Controller → Service → Repository → Database`.

## 8. Is Eloquent already a Repository?

No. Eloquent uses the **Active Record** pattern. This means the Model itself knows how
to save and find its own data. A Repository adds one more layer on top of Eloquent.

## 9. Problems with Repository

- It adds extra code for a simple CRUD app.
- It can hide good Eloquent features, like eager loading and scopes.
- It can be too much work if the data source will never change.

## 🎯 Main Idea

Repository separates **what data you need** from **where the data comes from**. It is
good for apps that may change the data source, or need easy testing. It may be too much
for a very simple app.

## الترجمة بالعربي

### 1. ايه هو الـ Repository؟
Repository عبارة عن layer بيقعد وسط الـ business logic (controllers, services) وبين
البيانات (database, API, cache). الكود بتاعك بيتكلم مع الـ Repository مش مع قاعدة
البيانات مباشرة.

### 2. ليه بنستخدمه؟
- بيفصل الـ business logic عن مصدر البيانات.
- سهل نغيّر مصدر البيانات بعدين (MySQL → API → cache).
- أسهل في الاختبار — نقدر نستخدم Repository وهمي بدل قاعدة بيانات حقيقية.
- بيجمّع كود الاستعلامات كله في مكان واحد.

### 3. مثال في لارافيل
زي ما هو فوق: `interface UserRepositoryInterface` و `EloquentUserRepository` بتنفذه،
والـ Controller بياخد الـ interface عن طريق الـ constructor.

### 4. Repository vs Eloquent Model
| Eloquent Model | Repository |
|---|---|
| جدول/صف واحد في قاعدة البيانات | layer فوق مصدر البيانات |
| مربوط بشكل كبير بالـ ORM | ممكن يخبّي الـ ORM ورا interface |
| صعب نغيّر مصدر البيانات | سهل نغيّر مصدر البيانات |

### 5. ليه بنستخدم Interface؟
الكود بتاعنا بيعتمد على `UserRepositoryInterface` مش على الكلاس الحقيقي. فنقدر نغيّر
مصدر البيانات (Eloquent → API)، أو نستخدم Repository وهمي في التستات، من غير ما نغيّر
باقي الكود.

### 6. الـ Binding في service container
زي الكود فوق: `$this->app->bind(UserRepositoryInterface::class, EloquentUserRepository::class);`

### 7. Repository vs Service Layer
- **Repository**: بس بيجيب ويحفظ بيانات.
- **Service**: فيه الـ business logic، وممكن يستخدم أكتر من Repository.

المسار الطبيعي: `Controller → Service → Repository → Database`.

### 8. Eloquent مش أصلاً Repository؟
لأ. Eloquent بيستخدم باترن **Active Record**، يعني الموديل نفسه عارف يحفظ ويجيب بياناته.
الـ Repository بيضيف layer زيادة فوق Eloquent.

### 9. مشاكل الـ Repository
- بيضيف كود زيادة في تطبيقات CRUD بسيطة.
- ممكن يخبّي مزايا كويسة في Eloquent زي eager loading والـ scopes.
- ممكن يبقى تعب زيادة لو مصدر البيانات مش هيتغير أبدًا.

### 🎯 الفكرة الأساسية
الـ Repository بيفصل بين **ايه البيانات اللي محتاجها** وبين **منين البيانات جاية**.
كويس للتطبيقات اللي ممكن تغيّر مصدر البيانات أو محتاجة اختبار سهل. ممكن يبقى مبالغة
لتطبيق بسيط جدًا.
